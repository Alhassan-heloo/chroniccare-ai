# ChronicCare AI — الجيل الجديد من التصميم

> Historical design report. Current visual direction and verification are documented in [Living Evolution](../../docs/living-evolution-redesign.md). Ocean Graphite character is retained while prior layout restrictions and the rejected ChronicCare 4.0 direction are superseded.

## النطاق والفحص الأولي

رُوجعت الصفحات والمسارات الحالية، وملفا `globals.css` وThemeProvider، وهيكل الأدوار
وProtectedRoute، وقواميس i18n، ومكونات لوحة المريض، وتقارير التصميم السابقة
`VISUAL_REDESIGN.md` و`PUBLIC_DESIGN_FOUNDATION.md` واختبار المتصفح الموجود.
حُفظت التعديلات غير الملتزم بها قبل هذه الجولة؛ لم تُحذف أو تُرجع إلى Git.

قبل تعديل الواجهة شُغّلت النسخة الموجودة فعليًا على `http://127.0.0.1:5199`، والتُقطت
48 حالة BEFORE. بعد التنفيذ شُغّل المشروع نفسه على المنفذ نفسه، وأُعيد التقاط الحالات الـ48
باللغات والعروض والثيمات نفسها، مع 38 حالة إضافية للتفاعل وهيكل الأدوار.

## التغيير البصري الفعلي

1. **رئيسية جديدة بالكامل في تركيبها:** Hero داكن بعرض النافذة، وعنوان «رعايتك الصحية، بذكاء مختلف.»
   وترجمته الإنجليزية الطبيعية. لم يعد Hero مقسومًا إلى نص ومعاينة جانبية.
2. **معاينة منتج مستقلة كبيرة:** React/CSS، لا صورة ثابتة؛ قراءات الضغط والسكر واتجاه الأسبوع
   ومتابعة العادات والأدوية وروابط الأقسام التوضيحية. يستمد الرسم قيمه من `demoWeeklyMeasurements`
   الموجودة دون تعديلها. المعاينة للعرض فقط ومعلّمة ببيانات مثال، وليست سجلًا طبيًا أو تقييمًا.
3. **Bento غير متماثل:** كتلة قياسات كبيرة، واتجاهات، وتقدم عادة، وجدول أدوية، وتقارير، ومعاينة مساعد.
   لا شهادات أو مستخدمون أو شركات أو تسعير وهمي.
4. **رحلة منتج:** إنشاء حساب، التسجيل والتنظيم في المساحة التجريبية، ثم مراجعة التقدم.
5. **مساعد صريح الحدود:** قسم عالي التباين وسؤال مستقبلي توضيحي، مع توضيح أن النموذج غير متصل
   وأنه لا توجد إجابة مولدة أو تشخيص أو توصيات علاجية.
6. **تنقل عام متجاوب:** الشعار والروابط والتفضيلات والحسابات على الكمبيوتر؛ قائمة إفصاح على
   الجوال واللوحي، قابلة للوحة المفاتيح، تغلق بـEscape وتعيد التركيز إلى زر الفتح.
7. **الدخول والتسجيل:** الحفاظ على النماذج ومنطقها، مع تركيب حساب جديد، وتبديل موضع النموذج
   والقصة على الكمبيوتر، وإضافة معاينة أسبوعية فعلية من بيانات المثال، وتبسيط الجوال.
8. **هيكل تطبيق جديد:** شريط جانبي كحلي كامل ارتفاع النافذة يتضمن العلامة والتنقل بحسب الدور،
   وشريط علوي داخل مساحة العمل، وتنقل جوال واضح. محتويات صفحات الطبيب والإدارة كما هي.
9. **لوحة المريض:** أحدث قراءتين في مساحة مميزة بجوار المخطط الأسبوعي؛ ملخصا الدواء والنشاط
   في شريط منفصل؛ سجل المهام والمساعد والتقارير أسفلها. لم تعد أربع بطاقات متشابهة تعلو
   مخططًا بجوار المهام كما في التصميم السابق.

اعتمدت الهوية Midnight Navy `#071427` وElectric Blue `#2563EB` وCyan `#17B5BE`، مع درجات
نصوص وحدود تناسب التباين في الثيمين، والإبقاء على Cairo ومقاييس الأساس الموجودة.
لا صور مخزنة، أو توهجات، أو اعتماديات جديدة، أو إعادة بناء للتطبيق.

- `src/components/public/PublicHeader.tsx`: التنقل وقائمة الجوال والإتاحة.
- `src/components/public/PublicLayout.tsx`: نطاق الهوية وروابط الأقسام الإضافية.
- `src/components/public/CarePreview.tsx`: معاينة المنتج الجديدة من أمثلة المشروع.
- `src/components/public/PreviewTrend.tsx` **جديد**: رسم توضيحي مشترك لقيم الضغط الانقباضي السبعة.
- `src/components/public/ProductFeatures.tsx` **جديد**: Bento ومرئيات الميزات.
- `src/components/public/AssistantPreview.tsx` **جديد**: معاينة غير متصلة مع إفصاح واضح.
- `src/components/layout/DashboardLayout.tsx`: فصل الشريط الجانبي ومساحة العمل.
- `src/components/layout/Sidebar.tsx`: العلامة داخل الشريط؛ تنقل الأدوار الموجود محفوظ.
- `src/i18n/locales/ar.ts` و`en.ts`: العنوان و41 مفتاحًا جديدًا متطابقًا، دون حذف مفاتيح سابقة.
- `scripts/smoke.tsx`: تحقق من تركيب Hero/Bento/المساعد وهيكل اللوحة والشريط.

توجد ملفات أخرى معدلة مسبقًا في Git، ومنها محتوى صفحات القياسات والأدوية والعادات والتقارير
والمصادقة والمسارات؛ لم تُعَد كتابتها في هذه الجولة. التغير المشترك في الألوان والهيكل يصل إليها،
لكنه ليس إعادة تصميم لمحتواها.

## نتائج التحقق الفعلية

| الفحص | النتيجة |
| --- | --- |
| TypeScript للتطبيق والسكربتات | PASS |
| ESLint | PASS |
| Smoke | PASS — 14 مسارًا، قواميس، تحقق، CRUD، التزامن والتقارير وأمثلة الأسبوع |
| Translation checks | PASS — 331 مفتاحًا متطابقًا وplaceholders متوافقة |
| Production build | PASS |
| `git diff --check` | PASS |
| BEFORE في Edge | PASS — 48 لقطة حالة |
| AFTER في Edge | PASS — 86 حالة و6 مجموعات تفاعل |

التغطية الأساسية **بالعربية RTL والإنجليزية LTR**، لكل من `/` و`/login` و`/register`
و`/patient/dashboard`، بارتفاع viewport يساوي 960px:

| العرض | الثيم |
| --- | --- |
| 320px | Light |
| 390px | Dark |
| 430px | Light |
| 768px | System مع تفضيل OS Light |
| 1024px | Dark |
| 1440px | Light |

عند 390px باللغتين اختُبرت الأوضاع الثلاثة وتغير OS إلى Dark وLight في System، والاستمرارية
بعد إعادة التحميل. ليست هذه جميع التوافيق الممكنة لكل حجم وثيم.

اختبارات التفاعل تؤكد:

- تبديل اللغة المتكرر مع حفظ المسار وquery وhash وقيم نموذج التسجيل.
- القائمة العامة، Escape وإعادة التركيز، وروابط الأقسام والنقر المتكرر.
- التحقق ورسائل النجاح والخطأ، إظهار كلمة المرور، وتعطيل النموذج ومؤشر الانتظار.
- إنشاء حساب تجريبي في fixtures، والحساب المكرر، والبيانات الخاطئة، والدخول والخروج،
  وعدم حفظ الرمز في Storage، ومسح بيانات React Query عند الخروج.
- التنقل إلى Dashboard، مفاتيح المخطط وtooltip، قائمة More والتنبيه التجريبي.
- CRUD القياسات والتحقق والفلاتر وتزامن آخر قراءة بين Dashboard/Reports، مع الإضافة والحذف
  والعودة إلى 14 قراءة تمثل الأيام السبعة.
- CRUD العادات وتقدمها والنصوص الطويلة المختلطة الاتجاه، وCRUD الأدوية وتسجيل الجرعة وإلغائها.
- شاشات الطبيب والإدارة الحالية عند 1440px/EN/Light و390px/AR/Dark، وروابط الدور ورفض مسار المريض.

النتائج: صفر أخطاء runtime، وصفر تحذيرات Console غير متوقعة، وصفر حالات فشل تباين نصوص
في العناصر المرئية المشمولة بالمسبار. لا overflow أفقي للوثيقة أو تجاوز لحدود الشاشة أو تداخل
في مجموعات التحكم المفحوصة. فحص التباين يحسب لون النص وخلفيات CSS المركبة ويطبق 4.5:1
للنص المعتاد و3:1 للنص الكبير؛ لا يغني عن تدقيق WCAG شامل.

اختُبر تركيب الأقسام الجديدة على المسار المخدوم، وأن Hero بعرض النافذة والمعاينة أسفله وليست
داخله، وأن Bento يضم ست كتل. رُوجعت صور فعلية قبل وبعد، لا نتائج البناء وحدها.

## إعادة التشغيل والحدود

من `apps/frontend`، مع توفر Playwright وEdge كما في البيئة الحالية:

```powershell
# عند الحاجة: مسار حزمة Playwright المثبتة أصلًا محليًا، لا يلزم اعتماد جديد للمشروع.
$env:PLAYWRIGHT_MODULE_PATH = 'C:\path\to\existing\node_modules\playwright'
npm.cmd run test:design-browser -- --next-design

# معاينة التطوير، عند خلو المنفذ:
npm.cmd run dev -- --host 127.0.0.1 --port 5199 --strictPort
```

الاختبار يشغّل ويوقف Vite الخاص به ويرفض المنفذ المشغول. استجابات المصادقة fixtures داخل
المتصفح؛ لم يُجر اتصال بالخلفية أو PostgreSQL. لم تتغير عقود API أو إدارة الجلسات أو الأدوار
أو React Query أو الحسابات أو ملفات بيانات المثال. لم تُضف وظيفة AI فعلية.

بعد انتهاء الاختبارات شُغّل خادم معاينة Frontend منفصل محليًا على `http://127.0.0.1:5199/`
للمراجعة، وتحقق HTTP 200. لم يُشغّل Backend. يُفضّل استخدام العرض التجريبي للمراجعة دون خادم.
يجب إيقاف هذه المعاينة قبل إعادة الاختبار الذي يحتاج المنفذ نفسه؛ يمكن طلب إيقاف عملية المعاينة
التي شغّلها Codex فقط، دون إنهاء عمليات أخرى على الجهاز.

بقي تحذيرا Zod الخاصان بتعليقات PURE في build، وتنبيهات فاحص المفاتيح الديناميكية/المحتمل
عدم استخدامها. لم تُخفَ تحذيرات ولم تُحذف مفاتيح لتجاوزها. لا تحذير حجم حزمة زائد في البناء.

استخدمت الأوامر نسخة Node عاملة متاحة بالفعل في بيئة الأدوات مع PATH مؤقت فقط، لأن النسخة
الافتراضية لم تكن قابلة للاعتماد في الجولة السابقة؛ لا تثبيت أو تغيير دائم للبيئة.
الاختبار في Edge على Windows عبر Vite، وليس اختبارًا مستقلاً لـSafari أو أجهزة جوال فعلية
أو قارئ شاشة. البناء الإنتاجي تحقق، لكن الصور ليست من خادم production preview.

## المرحلة التالية فقط بعد المراجعة

تبقى محتويات صفحات Measurements وMedications وHabits وReports وDoctor وAdmin لإعادة
التصميم لاحقًا، مع بقاء وظائفها الحالية متاحة. لم يتغير الفرع `main`، ولم يُنفّذ commit أو push،
ولم يتغير Backend أو Database.
