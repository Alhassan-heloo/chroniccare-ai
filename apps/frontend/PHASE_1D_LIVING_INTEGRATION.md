# Phase 1D — Living 3.3 Design Integration

26 أكتوبر 2026 — التطبيق الأساسي `apps/frontend` فقط. لم تبدأ Phase 1E.

## النتيجة والنطاق

نُقلت تركيبة Living 3.3 المعتمدة إلى الرئيسية والشريط العام وصفحتي الدخول والتسجيل، مع إبقاء React Router وAuthProvider وI18nProvider وThemeProvider وAPI والصلاحيات كما هي. لم يُبنَ تطبيق بديل أو Backend جديد. لا اعتماديات أو خطوط جديدة، ولا commit/push أو تغيير فرع.

استُخدمت إرشادات Sites للمعاينة المحلية والسرد القائم على وظائف المنتج الموجودة؛ لا تسجيل خدمة أو نشر أو تغيير استضافة.

## الفحص وخط الأساس

- فُحصت شجرة الواجهة، المسارات العامة والمحمية، نماذج الحسابات وAPI، الموفّرات والكتالوجات والتنسيق، مكونات UI، الأنماط العامة والخط المحلي، مخازن بيانات الصحة، ومسارات الطبيب/المدير وplaceholders.
- فُحص مرجع Living ومكوناته وتقارير 3.2 و3.2.1 و3.3؛ لا افتراض لتطابق معماري بينه وبين التطبيق.
- قبل الدمج: TypeScript وESLint و359 مفتاحًا ثنائي اللغة واختبارات smoke وProduction build نجحت. ظهرت تحذيرات تعليقين داخل Zod، موجودة قبل العمل. رفض esbuild داخل sandbox قراءة الإعدادات؛ نجح بعد السماح بالتنفيذ خارج القيد، دون تعديل الإعدادات.
- صُوّر التطبيق قبل التعديل في 48 حالة، مع 24 صورة للمرجع وحالات إجراء الحساب. فحص اتصال `chroniccare_test` نجح؛ المهاجرتان 001 و002 موجودتان. لا مهاجرات جديدة أو تعديل schema.
- لم يوجد ملف المقترح الأصلي أو تقرير مستقل بتاريخ 25 أكتوبر. التفاصيل ومصفوفة الأدلة والمرحلة والتحقق في [PHASE_1D_REQUIREMENTS.md](./PHASE_1D_REQUIREMENTS.md). لا يُستبدل المقترح بتقرير المراجعة، ولا تُنسب إليه متطلبات مخترعة.
- كانت الشجرة تحتوي تعديلات كثيرة سابقة، بما فيها صفحات المريض والأنماط العامة. لم تُعدّل أو تُنسب إلى هذه الجولة.

## ما نُقل وما كُيّف

1. **تركيبة الرئيسية نفسها:** العنوان المركزي، Tidal Weave، فهرس القدرات، Canvas التفاعلي، منظور الأسبوع، التكوين المتدرج للأدوية والعادات، التقرير، معاينة المساعد والخاتمة. ليس مجرد نقل ألوان.
2. **الرسوم:** SVG الأصلي ثابت وزخرفي، Living Pulse مرتبط بالتفاعل، أسماء ورسوم الضغط/السكر ومقياس ديناميكي دون تصنيف طبي. نقاط الرسم قابلة للمؤشر والمفاتيح والمنزلق، وسجل نصي بديل.
3. **النظام البصري:** Ocean Graphite، Cairo المحلي، الأسطح والحدود والعمق والتدرجات والطباعة والحركة المتجاوبة. الأنماط كلها مقيدة بـ`.living-public`، وأسماء keyframes مسبوقة لتجنب التضارب. لم تُغيّر متغيرات `:root` الخاصة باللوحات الداخلية.
4. **المكونات:** مكيّف Button يستخدم `components/ui/Button` الموجود بدل تنفيذ زر تحميل/تعطيل ثانٍ. تبقى Input وFeedback وModal وCard الموجودة؛ أضيفت معالجاتها البصرية ضمن scope العام، دون استبدال واجهاتها أو تطبيق ذلك على المريض.
5. **الحسابات:** المرجع لا يحتوي صفحتي Login/Register حقيقيتين؛ لديه نوافذ إفصاح فقط. لذلك نُقلت لغته الفنية إلى النماذج الحقيقية مع الرسم والمعاينة والقصة، وبقيت الحقول والأخطاء وقيود كلمة المرور وتأكيدها وإخفاؤها والإرسال والتحميل وdemo وروابط العودة.
6. **الثيم:** الموفّر الموجود يحتفظ بـLight/Dark/System، لذلك يختلف رأس الصفحة قليلًا عن مرجع ذي مظهرين: حُفظ اختيار System، ومعه زر Motion Off. يتوزع رأس الهاتف على صفين ليبقى قابلًا للمس دون قص.
7. **المحتوى:** أضيف 96 مفتاحًا متناظرًا تحت `public.living`؛ المجموع 455. لا حذف أو استبدال للترجمات القديمة. مكيّف presentation يستدعي الكتالوج typed والتنسيق المركزي نفسه؛ لا قاموس runtime ثانٍ أو Intl بديل.
8. **معاينات صادقة:** القراءة من seed الأيام السبعة الموجود، لا من سجل المريض المتغير. تغييرات الجرعات والعادات في الصفحة العامة محلية ومعزولة. إجراء الحساب ينقل لمساره الحقيقي، وإجراء المساحة يدخل demo الحالي أو وجهة دور المستخدم. لا ادعاء AI متصل أو سجلات صحة محفوظة بالخادم.
9. **حماية الترجمة:** الجذر العام كله declarative، وجميع النصوص بداخله نُقلت إلى React/الكتالوج؛ ليس حاوية تحتوي نصوصًا عربية متروكة. MutationObserver بقي عالميًا كما هو للمناطق القديمة، ولم يُحذف أو يُعدّل.

## التوافق والانحدارات التي عولجت

- SVG في قصة الحساب تمدد 8px خارج الهاتف. ثُبت حجمه داخل الحاوية، دون `overflow-x:hidden` عالمي.
- تكييف أنماط الزر العام كان يتغلب على padding جرعة المرجع؛ خُفّض specificity للمكيّف العام بـ`:where` كي تحتفظ الأزرار المتخصصة بمقاساتها.
- اسم `.overline` في المرجع يطابق utility قائمة في Tailwind؛ ظهر خط فوق عنوان الرسم. أُلغي text-decoration لهذه الفئة داخل النطاق العام فقط، وأضيف حارس source/browser دون تعديل Tailwind أو المرجع.
- حُفظ رابط لوحة الدور الحقيقي بدل تحويله إلى زر فقط، وحُفظت حالة تحذير فشل logout حتى إذا مسح الموفّر المستخدم المحلي.
- اختبار المصادقة القديم كان ينتظر URL فقط قبل التعامل مع نموذج React التالي؛ نتج سباق متقطع بين login/register. أصبح ينتظر نوع حقول النموذج الجديد. لم يُغيّر منطق التطبيق أو يخفف assertions.
- اختبار aria-describedby الجديد احتاج فصل قائمة المعرفات بدل معاملتها معرفًا واحدًا. ومعاينة المساعد احتاجت انتظار ظهور المحتوى بعد الفتح؛ كانت تعمل أصلًا.
- فحص التباين القديم قرأ `color(srgb ...)` الناتج من color-mix كمقادير RGB من 0 إلى 255، فأعطى إخفاقات وهمية. أُصلح باستخدام محلل ألوان Canvas الأصلي مع cache و`willReadFrequently`؛ لم تُخفَ أخطاء تباين أو تُغيّر الألوان لإرضاء قياس خاطئ.
- فحص scope يمنع تسرب selectors، ويحرس بقاء متغيرات المؤشر على `.canvas-light` وحدها، مع تنظيف RAF/listeners. لا حلقة أنيميشن مستمرة جديدة أو blur جديد ثقيل.

## الأداء وحجم النقل

مرجع Living 3.3 والتطبيق الكامل خُدما كـProduction على 5206/5179، بلا HMR أو throttling مقصود. **لا ادعاء بتحسن الأداء أو تطابق كلفة التطبيق والمرجع.** ظهر P95 أعلى في التطبيق الكامل. هذه ليست مقارنة معزولة قبل/بعد الدمج: التطبيقان مختلفان في الموفّرات والأنماط والحزمة، ولم يُحفظ بناء التطبيق القديم كـbaseline قابل للتشغيل. نافذة Desktop نحو4.0s، لكن بعض إجراءات مرجع الهاتف مددت النافذة إلى4.5–5.5s مقابل نحو4.0s للتطبيق؛ لذلك لا تصح مقارنة Task/Style الهاتف كتحسن نسبي. حُفظت جميع العينات، ولم تُحذف الجولات الأعلى P95.

الجدول من إعادة القياس على الحزمة النهائية بعد إيقاف Dev Server، دون بناء أو تصوير بالتوازي. الدفعة الأولى محفوظة كاملة في `performance-initial/`؛ فيها P95 هاتف التطبيق33.2ms، بينما أعطت الإعادة16.9ms دون تعديل مكونات الواجهة. هذا تفاوت بين الدفعات، وليس تحسنًا من إصلاح برمجي. بقي P95 Desktop33.3ms في الدفعتين، لذلك يبقى اعتماد سلاسته المرئية مشروطًا بفحص مستقل؛ لا يُقدَّم قيد الأداء كاختبار PASS شامل.

المؤشرات من rAF وCDP وليست FPS معروضًا فعليًا أو GPU utilization أو INP معتمدًا. CLS هنا رصد تجميعي منذ التحميل مع استبعاد recent-input، وليس قياسًا ميدانيًا كاملًا لنافذة CLS. لا معيار نجاح/فشل تعسفي أخفى هذه الحدود. يلزم فحص Edge المرئي وهاتف فعلي قبل اعتماد أداء شامل أو إضافة حركة إضافية. تحسين 3.2.1 المحدد (عزل متغيرات الإضاءة) محفوظ ومختبر؛ لم تُخترع معالجة أداء أخرى دون دليل مصدر محدد.

قبل الدمج: CSS gzip20.29kB، main JS gzip108.92kB. البناء النهائي: CSS218.74kB / gzip37.10kB، main JS396.48kB / gzip119.49kB، vendor-ui gzip15.19kB مقابل14.77kB. هذه زيادة فعلية لنقل اللغة الفنية والمكونات والأيقونات؛ لا ادعاء أن النقل بلا كلفة. لم تُضف مكتبات، وبقيت الرسوم SVG/CSS والخط المحلي نفسه.

## الجاهزية والحدود

Phase 1D منقولة وظيفيًا وبصريًا ضمن نطاقها؛ يمكن بناء **1E بعد موافقة منفصلة** على المكونات والرموز والموفّرات نفسها دون إعادة بناء. لا تُطبق الأنماط العامة الجديدة على لوحة المريض تلقائيًا؛ نقلها مقصود للمرحلة التالية.

قبل اعتماد شامل: مراجعة بشرية للجماليات، هاتف فعلي، Edge مرئي، تكبير المتصفح الأصلي200%، وقارئ شاشة. لم يُختبر Firefox/Safari أو تقييم WCAG كامل أو أمان/جاهزية نظام صحي إنتاجي. P95 الأعلى في المقارنة التشخيصية قيد معلن، لا نتيجة تحسن. المقترح الأصلي وتقرير25أكتوبر مطلوبان لإغلاق بنود التتبع غير المتاحة. لا AI/FCM/حفظ بيانات صحية حقيقي أُضيف ضمن التصميم، ولا تغيير لخارطة التطوير أو قواعد المصادقة.
