# Living 3.1 — تقرير التنفيذ والتحقق

تاريخ التحقق: 2026-10-24. النطاق حصريًا `design-prototypes/chroniccare-living`.

## النتيجة المرئية

- الحفاظ على Ocean Graphite وCairo والألوان الوظيفية وهوية الصفحة وترتيب أقسامها.
- Health Canvas أصبح أقرب إلى أداة استعراض بيانات: تدرج مادي خفيف، تمييز القراءة المختارة، ترتيب أوضح لحجمي القيم، وعدسة خلف اليوم المختار وشبكة يومية خافتة.
- تتغير منحنيات الضغط والسكر بانتقال SVG/CSS مدته 600ms، دون إعادة تركيب أزرار النقاط أو فقدان التركيز. يوجد مسار SVG صحيح بديل للمتصفحات التي لا تحرك خاصية CSS d.
- تظهر القيمة الصحيحة مباشرة؛ الحركة تخص دخول النص نفسه، وليست عدادًا يمر بقيم صحية غير مسجلة.
- Living Pulse شريط انتقال ضوئي منحني Aqua/Blue، منفصل عن بيانات الرسم ومخفي عن قارئات الشاشة. يُعاد تشغيله عند تغيير النوع/اليوم، وليس محاكاة ECG أو مؤشر اتصال/تحليل طبي.
- إضاءة المؤشر تحدث مرة واحدة كحد أقصى لكل إطار، بلا إعادة تصيير React من تأثير الإضاءة وبلا حلقة JavaScript مستمرة. تتعطل على اللمس والحركة المخفضة.
- الإضاءة المحيطية تستخدم تدرجات موجودة وحركة translate بطيئة في الرئيسية فقط؛ لم تضاف مكتبة رسوم أو مؤثرات 3D أو صور أو طلبات شبكة خارجية.
- زر مستقل لإيقاف/استئناف الحركة، يحفظ التفضيل محليًا. تفضيل الجهاز للحركة المخفضة له الأولوية. يشمل الإيقاف انتقالات البيانات والتمرير البرمجي.

## إصلاحات التدقيق الستة

1. Skip to Content ينقل التركيز إلى main دون تعديل hash أو مسار لوحة المريض.
2. حارس تركيز لوحة المفاتيح يقيس حدود الهيدر والشريط الفعلية ويزيح التمرير فقط بالقدر اللازم. لا يعيد التركيز ولا يؤثر على نقرات المؤشر ولا يبدأ حلقة تمرير سلس.
3. حركة route أصبحت opacity فقط: لا transform على سلف للشريط الثابت؛ تم اختبار موضع الشريط أثناء دخول اللوحة، لا بعده فقط.
4. لون حدود الحقول الفاتحة مستقل عن حدود البطاقات: #71869a. التباين المحسوب في المتصفح مع الخلفية البيضاء 3.764:1 بدل 2.029:1 تقريبًا.
5. التحقق يحدد الحقل المتأثر ويربطه بـ reading-error. في حالة 120/130 يُركز الانبساطي، ولا يُعلّم الانقباضي الصحيح بأنه خاطئ. قواعد validReading نفسها لم تتغير.
6. Escape يعمل من زر قائمة الهاتف ومن عناصرها، ويعيد التركيز إلى زر القائمة.

تم كذلك منع التفاف إجراء إنشاء الحساب غير الضروري. لا تغيير في قواعد القياسات أو الجرعات أو العادات أو حساب التقرير.

## الأداء والحدود

- نتيجة البناء النهائي: JavaScript نحو 283.72 kB، و88.12 kB gzip؛ CSS نحو 78.66 kB، و15.05 kB gzip. هذه أحجام فعلية، وليست قياس FPS أو Core Web Vitals.
- لا اعتماديات جديدة. التدرجات لا تعتمد على blur متحرك. تأثير المؤشر يلغي الإطار السابق، ينظف المستمعين عند إزالة المكوّن، ولا يعمل على أجهزة اللمس.
- استُخدم متصفح حقيقي بمحاكاة viewport؛ ليس اختبارًا على هواتف فعلية أو CPU مخفّض.
- أدوات المتصفح المتاحة لا تعرض محاكاة OS prefers-reduced-motion أو Performance tracing. تم اختبار زر الإيقاف فعليًا، والـhook لحالتي OS في اختبارات الوحدة، وقواعد CSS. لا ندّعي اختبار تغيير إعداد OS داخل المتصفح أو قياس FPS/LCP/INP.
- يلزم تحقق يدوي مختصر على جهاز فعلي: تفعيل Reduce Motion قبل الفتح، التأكد من عدم الحركة وتعطيل زر استئنافها وفق إعداد الجهاز، ثم استعادة إعداد المستخدم. يُفضّل كذلك فحص Safari/Firefox للحركة البديلة.
- الحسابات والمساعد والإشعارات تظل تجريبية كما كانت؛ لم يضف اتصال Backend أو AI أو بيانات مرضى.
- منع العزل أول تشغيل Vite والبناء من قراءة مسار config؛ نجح التشغيل والبناء بعد الموافقة على التنفيذ خارج العزل، دون تغيير الإعدادات.
